## Отложено: безопасный сброс и полное восстановление
- [ ] Управляемый worker и достоверное подтверждение остановки исходного процесса. Сейчас приложение не может получить такое доказательство; тайм-аут и отсутствие heartbeat недостаточны.
- [ ] Fencing внешних Docker-операций и идентификация ресурсов по попытке: запрет записи старого результата в БД не останавливает уже выполняющийся Docker-вызов.
- [ ] Поиск orphan-контейнеров и сохранение намерения создания до Docker. Диагностика текущего этапа проверяет только известные container_id.
- [ ] После этих гарантий спроектировать явное восстановление/сброс review, проверку результата и безопасный повтор; пока доступна только диагностика и ручная отметка без разблокировки.
- [ ] Сериализация отдельных legacy stop/restart-действий с запуском инфраструктуры: текущая проверка запрещает их при уже установленном deploying/failed/review, но не является общей блокировкой Docker.
- [ ] Отдельная политика остановки после finished и дальнейшего удаления; сейчас завершение Docker не изменяет.
- [ ] Ограничения размера/пагинация диагностики, срок хранения журналов, метрики и уведомления о незавершённых попытках. Общий бюджет диагностики: сейчас тайм-аут 5 секунд на Docker-запрос, суммарное время растёт с числом сервисов.
- [ ] Удобная детализация отказа проверки условий и безопасные коды ошибок. Сейчас сообщения намеренно фиксированные, без сырых SDK-исключений и traceback.
