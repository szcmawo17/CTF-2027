Обновлено: 2026-10-21. Источник: ревизия кода ветки main и ручные проверки, сообщённые разработчиком.

## Текущий этап
Рабочий прототип Django + Docker. Следующий этап: проектирование пользователей, команд и участия в соревнованиях.

## Реализовано в коде
- Django-проект config и приложение competitions.
- Модели Competition, Team, Service, TeamService и миграции 0001–0008.
- Страница списка соревнований и Django Admin.
- Создание TeamService, запуск соревнования и развёртывание контейнеров через Docker SDK.
- Остановка и повторный запуск контейнеров из Django Admin.
- Загрузка DJANGO_SECRET_KEY из .env (сам .env игнорируется Git).

- Разработчик сообщил об успешном выполнении python manage.py check 2026-10-21.

## Не реализовано
- Регистрация, вход/выход и пользовательский профиль вне Django Admin.
- Членство пользователей в командах, роли капитана и приглашения.
- Участие независимых команд в нескольких соревнованиях.
- Раунды, расписание, флаги, чекеры, подсчёт очков и рейтинг.
- Полноценные уязвимые сервисы и шаблоны организаций.
- Изоляция команд и безопасный жизненный цикл Docker-инфраструктуры.
- Журнал событий, мониторинг действий, аналитика.
- Автоматические тесты (competitions/tests.py — шаблон).

## Выявленные технические долги
1. В Competition дважды объявлены name и description.
2. Team жёстко связана с Competition через ForeignKey; понадобится модель участия команды.
3. В TeamService нет ограничения уникальности пары team/service.
4. Docker-образ ctf-test-service захардкожен; опубликованные порты доступны на интерфейсах хоста.
5. Нет надёжного отката при частично неуспешном развёртывании; состояние БД может расходиться с Docker.
6. Удаление объектов Django не синхронизировано с удалением контейнеров.
7. DEBUG=True и SQLite — только для локальной разработки.
8. Нет автоматических тестов, подтверждающих поведение.

## Следующее действие
Спроектировать модель пользователей и независимых команд; перед изменением существующих моделей определить стратегию миграции данных и написать первые тесты.
