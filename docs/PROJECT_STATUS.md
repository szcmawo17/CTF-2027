# PROJECT_STATUS — Attack/Defense CTF Platform

Обновлено: 2026-10-23. Источник: ревизия GitHub main и результаты локальных проверок разработчика.

## Текущий этап
Стабилизация существующего Django + Docker прототипа. Блок безопасной локальной публикации портов и базовой синхронизации завершён. Следующий блок — частичные сбои развёртывания.

## Реализовано в коде
- Django config, приложение competitions, миграции 0001–0008.
- Модели Competition, Team, Service, TeamService, Django Admin и список соревнований.
- Создание, остановка, повторный запуск Docker-контейнеров тестового Flask-образа.
- Защита deploy/restart от повторного запуска контейнеров с небезопасным PortBindings.
- Публикация новых контейнеров только на 127.0.0.1; динамические порты.
- sync_team_service_status для ручной сверки с Docker, включая stopped и missing.
- Загрузка DJANGO_SECRET_KEY из .env.
- Пять модульных тестов Docker-проверок и синхронизации (mock).

## Проверено
- Разработчик сообщил об успешном python manage.py check, makemigrations --check --dry-run и пяти тестах.
- Разработчик подтвердил запуск четырёх контейнеров с 127.0.0.1 и проверку остановки/перезапуска.
- Разработчик подтвердил ручную сверку четырёх TeamService, статус stopped.
- Коммит с исправлением Docker и тестами прочитан из ветки main на GitHub.

## Не проверено или не реализовано
- Откат частично развёрнутой инфраструктуры при сбое.
- Автоматическая периодическая синхронизация, полноценное восстановление и удаление контейнеров.
- Изоляция сетей команд и ограничения ресурсов для настоящего Attack/Defense; localhost — лишь безопаснее для локального прототипа.
- Права участников, пользовательские команды, регистрация и участие в соревнованиях.
- Раунды, флаги, чекеры, рейтинг, наблюдаемость.

## Технический долг и архитектурные ограничения
1. Дубли объявлений полей Competition.name и Competition.description.
2. Team привязана к Competition — требует согласованного редизайна на этапе команд.
3. Нет ограничения уникальности (team, service) у TeamService.
4. Не обработан частичный сбой deploy_competition_services; изменения БД и Docker не атомарны.
5. Docker image ctf-test-service захардкожен; нельзя использовать текущую сетевую схему для настоящего CTF.
6. Удаление в Django не сопровождается безопасной очисткой Docker.
7. DEBUG=True и SQLite годятся только для локальной разработки.
8. Пять тестов не покрывают целостность моделей, запуск соревнования и ошибки Docker.

## Следующее действие
Спроектировать безопасную стратегию обработки частичного развёртывания, различающую уже работавшие контейнеры и созданные/запущенные текущей попыткой. Добавить тесты, затем исправить services.py.
